## 快速开始

需要 Python 3.8+（官方安装包自带 tkinter），**无需安装任何第三方库**。

```bash
cd S-AES

# 图形界面（推荐，验收就用这个）
python gui.py

# 命令行：教材例题，带每一轮中间状态
python main.py block -k 2D55 -p 6BA3 --trace

# 跑全部测试（44 项）
python main.py test
```

## 设计说明

**为什么用 tkinter 而不是 Qt？** 作业要求“使用你们自己最擅长的程序语言（C++/QT、Java+Swing、Python+QT 等）”，
而 tkinter 是 Python 标准库自带，组员和老师拿到代码**双击就能跑**，不需要装 PyQt。
界面层只有取值与显示，算法层完全独立 —— 若老师要求 Qt，只需照 `docs/开发手册.md` 第 9.1 节换前端，算法不用改。

**为什么强调交叉测试？** 单人实现时，加密和解密往往错在同一边（比如两边都把列混淆的行列搞反），
自己测自己永远是通的。只有和别人组的实现对接，才会暴露“我以为是标准，其实是我的约定”这类错误。

**三重加密为什么用 EDE？** `E(K3, D(K2, E(K1, P)))` 在 K1=K2 时退化为 `E(K3, P)`，
可以向下兼容单重加密，这也是 3DES 采用 EDE 的原因。

## 安全说明

S-AES 是教学模型，**不能用于任何真实场景**：密钥空间仅 2¹⁶，分组仅 16 bit，
两轮扩散不充分（实测输入差 1 bit、输出只差 3 bit），且没有认证机制。
第 4.2 关的中间相遇攻击实验也说明：多重加密并不能把安全性按密钥长度“翻倍”。

真实系统的正确做法：AES-128 起步 + CBC/GCM + 独立随机 IV + MAC 或认证加密。
